## Запуск

1. Установить пакеты:

```bash
npm install
```

2. Создать файл `.env` по примеру `.env.example`:

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_NAME=node_courses
DB_USER=postgres
DB_PASSWORD=your_password
PORT=3000
SESSION_SECRET=your_long_secret_value
BCRYPT_ROUNDS=10
```

3. Создать базу `node_courses` или запустить PostgreSQL в Docker (пароль `postgres`):

```bash
docker compose up -d
```

4. Добавить начальные данные (необязательно):

```bash
npm run seed
```

5. Запустить приложение:

```bash
npm start
```

## Создание администратора

При регистрации все пользователи получают роль `user`. Чтобы сделать администратора, нужно зарегистрировать пользователя, поменять роль в базе и войти заново:

```sql
UPDATE "Users" SET role = 'admin' WHERE email = 'admin@example.com';
```

## Маршруты аутентификации

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/register` | Форма регистрации |
| POST | `/register` | Создание пользователя |
| GET | `/login` | Форма входа |
| POST | `/login` | Проверка данных и вход |
| POST | `/logout` | Выход (удаление сессии) |
| GET | `/profile` | Профиль пользователя |

## Права доступа

| Действие | Гость | User | Admin |
| --- | --- | --- | --- |
| Просмотр курсов и преподавателей, поиск, фильтры | Да | Да | Да |
| Профиль, статистика | Нет | Да | Да |
| Добавление, редактирование, удаление курсов и преподавателей | Нет | Нет | Да |

Маршруты защищены middleware из `middleware/auth.js`:

- `isAuthenticated` — если пользователя нет в сессии, перенаправляет на `/login`;
- `isAdmin` — гостя перенаправляет на `/login`, а пользователю без роли `admin` возвращает `403` и страницу `403.ejs`.

Кнопки добавления, редактирования и удаления в шаблонах показываются только администратору, но это только удобство. Настоящая защита — middleware на маршрутах.

## Что было сделано

1. **Модель User:** `id`, `name`, `email` (уникальный), `password` (hash), `role` (по умолчанию `user`), `lastLogin`. В форме регистрации нет поля роли, поэтому выбрать `admin` нельзя.
2. **Пароли** обрабатываются через `bcrypt.hash()`, количество раундов берётся из `BCRYPT_ROUNDS`. При входе пароль сравнивается через `bcrypt.compare()`.
3. **Сессии.** `express-session` с секретом из `.env`, `resave: false`, `saveUninitialized: false`, cookie живёт 1 час. В сессии хранятся только `id`, `name`, `email`, `role`.
4. **Вход.** При ошибке всегда одно сообщение «Неверный email или пароль» (код `401`). При успехе обновляется `lastLogin` и открывается `/profile`.
5. **Выход** работает только методом POST. `GET /logout` возвращает `404`.
6. **`res.locals.currentUser`** устанавливается в `app.js`, поэтому пользователь доступен во всех шаблонах. В меню гость видит «Вход» и «Регистрация», пользователь — своё имя, «Профиль» и «Выход», администратор — ещё «Добавить курс» и «Добавить преподавателя».
7. **Валидация** сделана через `express-validator`. Правила для регистрации, входа, преподавателя и курса лежат в `middleware/validation.js`. Ошибки выводятся списком над формой, пароль обратно в форму не выводится.
8. **Ошибки.** `notFound.js` подключён после всех маршрутов, `errorHandler.js` — последним. Контроллеры передают ошибки через `next(error)`. Обработчик показывает страницу 404, 403 или общую страницу ошибки. Для ошибки 500 пользователь видит только общий текст, без stack trace и деталей SQL.
9. **Логирование.** `morgan('dev')` пишет в терминал. Второй logger пишет в файл `logs/requests.log` метод, URL, код ответа, время выполнения, дату и время.
10. **Журнал администратора.** Функция `logAdminAction` выводит в терминал строку при каждом добавлении, изменении и удалении курса или преподавателя.
11. **WebSocket.** Приложение запускается через `http.createServer(app)`, к серверу подключён Socket.IO. Объект `io` сохраняется через `app.set('io', io)`. Когда администратор добавляет курс, всем клиентам отправляется событие `courseCreated` с названием курса, именем преподавателя и временем. Скрипт `public/js/notifications.js` показывает сообщение в блоке «Уведомления». Сообщение исчезает через 8 секунд или по кнопке «Закрыть».

## Коды ответов

| Код | Когда возвращается |
| --- | --- |
| `400` | Некорректные данные в форме, удаление преподавателя с курсами |
| `401` | Неверный email или пароль |
| `403` | У пользователя нет роли `admin` |
| `404` | Нет такой страницы или записи, неправильный ID |
| `409` | Email уже зарегистрирован |
| `500` | Внутренняя ошибка сервера |

## Ответы для защиты

- **Аутентификация** — проверка, кто пользователь (вход по email и паролю). **Авторизация** — проверка, что этому пользователю разрешено делать (роль `user` или `admin`).
- **Сессия.** После входа сервер сохраняет данные пользователя у себя, а браузеру отдаёт cookie с номером сессии. При следующих запросах браузер отправляет cookie, и сервер по нему находит пользователя.
- `bcrypt` — превращает пароль в hash и сравнивает пароль с hash.
- `express-session` — создаёт и хранит сессии.
- `express-validator` — проверяет данные из форм.
- `morgan` — логирует HTTP-запросы.
- `socket.io` — передаёт сообщения от сервера в браузер в реальном времени.
